# 개발용 이미지 저장소

기본 루트는 `${user.home}/study/nas`이며, 이 Mac에서는 `/Users/junpyo/study/nas`다.
다른 경로나 실제 NAS 마운트로 이동할 때는 `LOCAL_STORAGE_ROOT` 환경 변수를 설정한다.

| 용도 | 하위 폴더 |
| --- | --- |
| 옵션상품 대표 이미지 | optionProduct |
| 옵션상품 상세 이미지 | optionProductDetail |
| 플레이스 | destination |
| 홈 추천 여행지 | recommendation |
| 여행 일정 | travelPlan |

파일은 `카테고리/yyyy/MM/dd/UUID.확장자` 형태로 저장된다. 파일명과 업로드 Content-Type을 그대로 신뢰하지 않고 지원 이미지 형식을 판별한다. JPG, PNG, GIF, WEBP를 최대 10MB까지 받는다. WebP는 JDK 기본 디코더가 없어 컨테이너 헤더와 크기를 검사한다.

MySQL/Oracle Flyway V30이 `TB_STORED_IMAGE`를 생성한다. 테이블에는 이미지 ID, 카테고리, NAS 루트 기준 상대 경로, Content-Type, 파일 크기, 생성 시각이 저장된다. 상품·플레이스·추천·일정의 기존 IMAGE_URL 필드에는 `/api/public/images/{이미지ID}`를 저장한다. 브라우저가 이 주소로 요청하면 서버가 이미지 테이블의 경로를 조회해 파일을 반환한다. 따라서 로컬 절대 경로를 브라우저에 노출하지 않는다.

파트너 상품 화면은 대표·상세 이미지, 관리자 플레이스·추천 화면과 일정 생성/수정 화면은 대표 이미지를 파일로 선택한다. 업로드 성공 후 상품/일정 등의 저장을 완료해야 해당 이미지가 연결된다. 업로드 중에는 저장을 차단한다. 관리자 이미지는 DESTINATION_MANAGE 권한, 파트너 이미지는 활성 파트너사 대표 권한이 필요하다. 일정 이미지는 로그인 사용자만 업로드할 수 있다. 이미지는 공개 조회 대상으로 취급한다.

기존 외부 이미지 주소와 `/uploads/...` 이미지는 계속 표시된다. 외부 이미지를 자동 다운로드하거나 기존 데이터를 일괄 수정하지 않는다. 홈의 고정 배너·아이콘 같은 프런트엔드 정적 리소스는 기존 배포 자산으로 유지한다. 선택 해제는 화면의 연결만 해제하며 파일을 삭제하지 않는다. 업로드 후 등록을 취소한 파일은 남으므로 추후 미연결 이미지 정리 작업이 필요하다.

실제 NAS로 옮길 때는 폴더 구조와 파일을 함께 복사하고 `LOCAL_STORAGE_ROOT`만 변경한다. DB와 파일 저장소를 함께 백업해야 한다.
